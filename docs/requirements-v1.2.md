## 1. システム概要

### 1-1. 目的

複数人が同じお題に対して回答し、チーム内の回答の一致率に応じて得点を獲得する、チーム対抗型のゲームアプリケーションを提供する。

司会者がPCからゲーム全体を管理し、参加者は各自のスマートフォンから参加する。

### 1-2. 利用者

| 利用者 | 人数 | 利用端末 | 役割 |
|---|---|---|---|
| 幹事（司会・運営・選手） | 5人 | PC 1台＋スマートフォン | 進行管理、運営、および選手として回答 |
| 参加者 | 25人 | スマートフォン | ルーム参加、回答、結果確認 |
| 会場スクリーン | - | 大型モニター等 | お題、回答、得点、順位の表示 |
| 合計 | 30人前後（上限は設けない） | - | 人数に応じてチームを編成 |

### 1-3. システム構成の概要

- 司会者用管理画面
- 参加者用画面
- 会場スクリーン用表示画面
- ゲーム進行・回答管理機能
- 得点計算・結果管理機能
- 参加者・チーム管理機能

## 2. ゲーム基本ルール

### 2-1. 基本設定

| 項目 | 仕様 |
|---|---|
| ゲーム形式 | チーム対抗戦 |
| チーム数 | 2以上（目安2〜6チーム） |
| チーム人数 | 固定しない（目安4〜6人） |
| 参加人数 | 30人前後（上限は設けない） |
| チーム編成 | 人数に応じて司会者が調整（例: 5チーム×6人。各チームに幹事1人） |
| チーム選択 | 参加者自身が選択（定員に達したチームは選択不可） |
| 回答方式 | 自由記述（20文字以内） |
| お題設定 | 司会者が事前設定 |
| 回答受付終了 | 司会者が手動操作 |
| 最終確認 | 回答締切後・公開前に30秒 |
| 回答公開 | 全チーム一斉公開 |
| ゲーム終了 | 全お題終了時 |

> 人数は固定しない。当日の欠席・遅刻・途中参加・早退を前提に、司会者が会場で調整できることを優先する。

### 2-2. 得点ルール

チーム内の回答を一致グループに分類し、**一致率**に応じて得点を付与する（10点満点）。

- 一致グループ：同じ回答をした2人以上の参加者
- 一致率：最大グループの人数 ÷ そのお題の回答者数
- 得点：一致率 × 10（四捨五入、0〜10点）
- 複数のグループがある場合、最も人数の多いグループのみを評価する

| 回答者数 | 最大グループ | 一致率 | 得点 |
|---|---|---|---|
| 6 | 6 | 100% | 10 |
| 6 | 5 | 83% | 8 |
| 6 | 4 | 67% | 7 |
| 6 | 3 | 50% | 5 |
| 6 | 2 | 33% | 3 |
| 6 | 0 | 0% | 0 |
| 5 | 5 | 100% | 10 |
| 5 | 4 | 80% | 8 |
| 5 | 3 | 60% | 6 |
| 5 | 2 | 40% | 4 |
| 4 | 4 | 100% | 10 |
| 4 | 3 | 75% | 8 |
| 4 | 2 | 50% | 5 |

> 人数が違うチームでも「何割が一致したか」で競うため、欠席や編成変更があっても公平に近づく。
> 全員一致なら人数に関係なく10点になる。

得点計算例（6人回答）

| 回答 | 最大グループ | 一致率 | 得点 |
|---|---|---|---|
| A・A・A・A・A・A | 6 | 100% | 10 |
| A・A・A・A・A・B | 5 | 83% | 8 |
| A・A・A・A・B・B | 4 | 67% | 7 |
| A・A・A・B・B・B | 3 | 50% | 5 |
| A・A・B・B・C・C | 2 | 33% | 3 |
| A・A・B・B・C・D | 2 | 33% | 3 |
| A・A・B・C・D・E | 2 | 33% | 3 |
| A・B・C・D・E・F | 0 | 0% | 0 |

### 2-3. 採点対象条件

- そのお題の**回答者数が4人以上**のチームを採点対象とする。
- 回答者数はお題ごとに判定する。開始時点の人数では固定しない。
- 回答者数は「そのお題に回答を送信した参加者」の人数とする。未回答者・退出者・スリープ中の参加者は含めない（回答済みで退出した場合は含める）。
- 途中参加者は、参加したお題から回答者数に含める。
- 回答者数が4人未満のチームは採点対象外とする。0点とは区別して表示する。
- チームの人数は固定しない（目安4〜6人）。
- 「全員一致ボーナス」は廃止する（一致率方式により、全員一致は自動的に10点になる）。

### 2-4. 順位決定

- 総合得点は、各お題の得点の合計とする。
- 同点の場合は次の順で決定する。
  1. 10点（全員一致）を獲得した回数
  2. 最終お題の得点
  3. 抽選

## 3. 参加者・チーム管理要件

### 3-1. ルーム管理

- 司会者は新しいゲームルームを作成できる。
- システムはルームコード（6桁英数字）を発行する。
- システムは参加用QRコードを発行する。
- 参加者はQRコードまたはルームコードで参加できる。
- 司会者は参加者一覧とチーム構成を確認できる。
- ルームコードはゲーム終了後、無効化される。

### 3-2. チーム管理

- チーム数は2以上。参加人数に応じて司会者が決める（目安2〜6チーム）。
- 1チームの人数は固定しない（目安4〜6人）。
- チームごとに定員を設定できる（既定6人）。司会者は変更できる。
- 各チームに幹事を1人配置する（推奨）。
- 幹事も選手として回答する。
- 参加者が自分で所属チームを選択する。定員に達したチームは選択できない。
- チーム名は司会者が設定する。
- 参加者の所属チームは待機中に変更できる。
- 司会者は参加者を別チームへ移動できる（ゲーム中も可）。
- 司会者はゲーム開始前にチームの追加・削除・定員変更ができる。
- 開始後に参加者の受け入れ先がない場合は、チームを追加できる。

### 3-3. 参加者登録

| 項目 | 必須 | 備考 |
|---|---|---|
| 参加者名 | 必須 | 20文字以内。同名は自動採番 |
| 所属チーム | 必須 | 満員不可 |
| ルームコード | 必須 | QRから自動入力 |

### 3-4. 途中参加

- ゲーム開始後も途中参加を認める。
- 途中参加者は次のお題から参加できる。
- 進行中のお題には参加できない。
- お題開始時点で、そのお題の回答者を確定する。
- チームが定員に達している場合は、司会者が定員を増やすかチームを追加して受け入れることができる。
- 途中参加者は、回答者数が少ないチームを優先して割り当てる（自動割当）。

### 3-5. 運営体制（幹事5人）

- 受付・Wi-Fi接続支援は、ゲーム開始前に5人で分担する。
- ゲーム中は1人がPCで進行を担当し、残り4人は選手として参加する。
- PC進行担当も選手であり、進行管理画面の「自分の回答」欄から回答する。
- 進行担当は問題ごとに交代できる（ログイン時に操作者名を切り替える）。
- トラブルの一次対応は進行担当が行い、手が離せない場合は近くの幹事が対応する。
- 欠席者がいてもゲームを止めない。欠員は無理に埋めず、そのまま実施する（採点は回答者数ベース）。

## 4. 回答管理要件

### 4-1. 回答入力

- 参加者はスマートフォンからお題を確認できる。
- 回答は自由記述形式とし、20文字以内とする。
- 回答送信後、送信済み状態を表示する。
- 回答受付終了前であれば何度でも修正できる。
- 回答受付終了後は、最終確認（第5章）のみ可能とする。

### 4-2. 回答未送信

- 未回答者が存在してもゲームを進行できる。
- 未回答者は一致グループに含めない。
- 未回答者は回答者数（得点の分母）にも含めない。
- 欠席そのものは得点に影響しないが、一致する人数が減るため最大グループは小さくなり得る。

### 4-3. 回答一致判定

- システムは回答を次の手順で正規化する。
  1. Unicode NFKC 正規化（全角／半角の統一）
  2. 前後の空白除去
  3. ひらがな／カタカナの統一
  4. 大文字／小文字の統一
  5. 末尾の句読点・記号の除去
- 正規化後に完全一致する文字列を自動でグループ化する。
- 司会者は異なる回答グループを統合できる。
- 司会者は統合を取り消せる。
- 回答グループの統合はチーム内に限定する。
- 統合した場合は、統合理由を全チームに表示する。
- 司会者の確認後、グループを確定する。
- 確定したグループをもとに得点を計算する。

例：

| 回答 | 自動判定 | 司会者の操作 |
|---|---|---|
| カレー | グループ1 | |
| カレーライス | グループ2 | グループ1と統合（理由: 同一料理） |
| 寿司 | グループ3 | |
| すし | グループ3 | 正規化で自動統合 |

## 5. 最終確認（公開前）

回答締切後、公開前に30秒間の最終確認時間を設ける。

| 項目 | 仕様 |
|---|---|
| 受付期間 | 回答締切後30秒 |
| 表示範囲 | 自分の回答のみ（他者・他チームの回答は見えない） |
| 修正方法 | 即時反映（申請・承認なし） |
| 修正回数 | 無制限（30秒以内） |
| 期間終了 | 自動的に公開へ移行 |
| 得点確定後 | 修正不可 |
| 履歴 | 修正履歴を保存 |

- 司会者は期間の短縮・延長、および即時の公開ができる。
- 参加者の「確定」操作は意思表示であり、フェーズを進めるものではない。

> 公開後に他チームの回答を見てから修正できると公平性が崩れるため、修正は公開前に限定する。

## 6. 参加者状態管理要件

### 6-1. 参加者状態

| 状態 | 説明 |
|---|---|
| ACTIVE | ゲーム参加中 |
| SLEEP | 本人による一時休止 |
| DISCONNECTED | 通信切断 |
| WITHDRAWN | 正式退出 |

### 6-2. スリープ機能

- 参加者は任意のタイミングで一時休止できる。
- スリープ中もチーム所属を維持する。
- スリープ中もチーム枠を占有する。
- スリープ中は新しい回答を送信できない。
- 既に送信した回答は保持する。
- 復帰後は次のお題から参加できる。
- 進行中のお題には途中参加できない。

### 6-3. 通信切断・復帰

- 通信切断を検知した場合、DISCONNECTED状態とする。
- 通信切断時もチーム枠を維持する。
- 再アクセス時に既存の参加者情報を復元する。
- 正式退出した場合はチーム枠を解放する。
- 再参加時は空き枠があれば新規参加として登録する。
- 退出・再参加があっても、採点はそのお題の回答者数をもとに行う（2-3）。

## 7. ゲーム進行管理要件

### 7-1. 司会者による進行操作

- ルーム作成
- ゲームルール設定
- チーム設定（追加・削除・参加者移動）
- お題登録・編集・削除・並べ替え
- ゲーム開始
- 回答状況確認
- 回答受付終了
- 最終確認の短縮・延長
- 回答公開
- 回答グループ確認・統合
- 得点確定
- 次のお題への移行
- 最終結果表示
- ゲーム終了

### 7-2. ゲーム状態

| 状態 | 説明 |
|---|---|
| WAITING | 参加者待機中 |
| READY | ゲーム開始可能 |
| ANSWERING | 回答受付中 |
| ANSWER_CLOSED | 回答受付終了 |
| FINAL_CHECK | 公開前の最終確認中（30秒） |
| REVEAL | 回答公開 |
| GROUPING | 回答グループの確認・統合中 |
| SCORED | 得点確定 |
| FINISHED | ゲーム終了 |

### 7-3. 状態遷移

| 遷移元 | 遷移先 | トリガ |
|---|---|---|
| WAITING | READY | 司会者が開始条件を満たしたと判断 |
| READY | ANSWERING | ゲーム開始 |
| ANSWERING | ANSWER_CLOSED | 司会者が締切 |
| ANSWER_CLOSED | FINAL_CHECK | 自動 |
| FINAL_CHECK | REVEAL | 30秒経過／司会者が公開 |
| REVEAL | GROUPING | 司会者が統合へ |
| GROUPING | SCORED | 司会者が得点確定 |
| SCORED | ANSWERING | 次のお題 |
| SCORED | FINISHED | 最終お題の終了 |

### 7-4. 基本進行フロー

1. 司会者がルームを作成する。
2. 参加者がルームに参加する。
3. 参加者が名前とチームを登録する。
4. 司会者が参加状況を確認する。
5. 司会者がゲームを開始する。
6. システムがお題を表示する。
7. 参加者が回答を入力・送信する。
8. 司会者が回答受付を終了する。
9. 30秒間の最終確認を行う（自分の回答のみ表示）。
10. システムが全チームの回答を公開する。
11. 司会者が回答グループを確認・統合する。
12. システムが得点を計算する。
13. 司会者が得点を確定する。
14. 次のお題へ進む。
15. 全お題終了後、最終結果を表示する。

- 回答公開後は全チームの回答を閲覧できる。
- 得点・順位は全参加者に表示する。
- 採点対象外のチームは0点と区別して表示する。

## 9. 認証・セキュリティ要件

### 9-1. 司会者認証

- 司会者はパスワード認証を行う。
- パスワードはハッシュ化して保存する。
- 認証されていない利用者は管理画面にアクセスできない。
- 司会者はログアウトできる。
- 操作ログには操作者名を記録する（5人運用のため、ログイン時に選択）。

### 9-2. 参加者認証・セッション管理

- 参加者はルームコードとQRコードで参加する。
- 参加者ごとに識別IDと端末トークンを発行する。
- 再接続時には既存の参加者情報を復元する。
- 公開前の回答を他の参加者が閲覧できないようにする。
- 他人の回答を修正できないようにする。
- ルームコードの試行にはレート制限を設ける。
- 全通信をHTTPSとする。検索エンジンにはインデックスさせない。

## 11. 非機能要件

| 分類 | 要件 |
|---|---|
| 操作性 | 初めて利用する参加者でも、QR読み取りから60秒以内に参加できる |
| UI | PC・スマートフォン双方に対応。インストール不要 |
| 応答性 | 回答送信から会場スクリーン反映まで2秒以内 |
| 同時利用 | 30人前後を想定。設計上は50人まで。チーム数は2〜6を最適化 |
| 柔軟性 | 当日の欠席・遅刻・途中参加・早退・チーム編成の変更に対応する |
| 可用性 | 一時的な通信切断から自動復帰できる。連続2時間の稼働に耐える |
| 視認性 | 会場スクリーンの本文は3m離れた位置から読める |
| データ保持 | 回答・得点・修正履歴を保存。ゲーム終了後24時間で削除 |
| セキュリティ | 司会者機能と参加者機能を分離。公開前の回答を保護する |
| 整合性 | 回答・得点の二重登録を防止する（冪等キー） |
| 保守性 | お題やルールを変更しやすい構成とする |

| D-03 | 採点対象 | 開始時点の登録人数で固定 → **v1.2でD-07に改訂** | 欠席・途中参加に対応できないため |
| D-04 | チーム数上限 | 5チーム（最大30人）→ **v1.2で上限を撤廃** | 当日の人数変動に対応するため |
| D-05 | 統合ポリシー | 表記揺れは自動、意味統合は司会者が理由付きで実施 | 司会者の裁量を残しつつ、恣意性を可視化する |
| D-06 | ゲームの位置づけ | 出し物枠のゲーム（5時間常設の構想は破棄） | ゲーム性を優先 |
| D-07 | 人数の固定 | **固定しない。チーム人数は可変、採点はお題ごとの回答者数ベースの一致率** | 当日の欠席・途中参加・編成変更に対応する |
| D-08 | 採点の最低人数 | **回答者4人未満は採点対象外** | 少人数での全員一致による満点を防ぐ |

## 14. 要件定義まとめ

### 以心伝心ゲーム

Requirements Specification / Version 1.2

- 司会者がPCからゲーム全体を管理する。
- 参加者はスマートフォンから参加する。
- チーム数・人数は固定しない（目安2〜6チーム、各4〜6人）。
- **一致率×10がそのお題の得点**（0〜10点）。全員一致は人数に関係なく10点。
- 表記揺れは自動正規化し、意味の統合は司会者が理由付きで行う。
- 回答締切後・公開前に30秒の最終確認を置く。
- 当日の欠席・途中参加・早退・一時休止・復帰に対応する。
- 得点・順位・最終結果を会場スクリーンに表示する。
