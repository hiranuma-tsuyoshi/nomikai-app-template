## 役割

| 役割 | 担当 | 画面 |
|---|---|---|
| 司会者 | 進行・お題・統合・採点 | `/host` |
| スクリーン | 会場投影 | `/stage?token=...` |
| 参加者 | スマホで回答 | `/play?code=...` |
| サブ幹事 | 参加者の入場支援・トラブル対応 | 参加者画面 |

- [ ] お題を確定した
- [ ] チーム数・定員を決めた
- [ ] 会場Wi-Fiでスマホから接続できるか確認した

### 前日

- [ ] `npm test` / `npm run lint` / `npm run build` が成功
- [ ] `smoke:live` が成功
- [ ] 30人規模の負荷テストが成功（可能なら）
- [ ] スクリーンURLのtokenを控えた
- [ ] 予備の司会者端末を用意した
- [ ] `game_states` のバックアップを取得した

### 負荷テスト

本番URLに対して、参加 → 一斉回答 → 締切 → 公開までを確認します。

```bash
BASE_URL=https://your-app.vercel.app \
HOST_KEY=your-host-key \
ROOM_CODE=4821 \
TEAM_COUNT=5 \
PLAYER_COUNT=30 \
npm run load:live
```

PowerShell:

```powershell
$env:BASE_URL="https://your-app.vercel.app"
$env:HOST_KEY="your-host-key"
$env:ROOM_CODE="4821"
$env:TEAM_COUNT="5"
$env:PLAYER_COUNT="30"
npm run load:live
```

- `ROOM_CODE` / `TEAM_COUNT` は本番設定に合わせる
- 検証スクリプトは終了時に `WAITING` へ戻し、お題を復元する
- `smoke:live` / `review:live` / `load:live` は**同時に実行しない**

## ゲームの流れ

```text
WAITING
  ↓ ゲームを開始
ANSWERING（回答受付）
  ↓ 回答を締め切る / 時間切れ
FINAL_CHECK（30秒の最終確認）
  ↓ 今すぐ公開する / 時間切れ
REVEAL（回答公開）
  ↓ グループ統合へ
GROUPING（意味統合）
  ↓ 得点を確定する
SCORED（得点発表）
  ↓ 次のお題へ / 最終結果を表示
ANSWERING ... → FINISHED（最終結果）
```

### 開始

1. 参加者が揃ったら「ゲームを開始」
2. お題が凍結される
3. 回答時間が終わると自動で締切、または手動で締切

### 最終確認

- 回答締切後、30秒間は参加者が回答を修正できる
- 司会者は `−30秒` / `＋30秒` で調整できる
- 「今すぐ公開する」で即時公開

### 回答公開・統合

- 表記ゆれは自動で正規化される
- 意味が同じ回答は司会者が理由を付けて統合する
- 統合は同じチーム内のみ。取消可能
- 統合理由は全チームに表示される

### 採点・次へ

- 「得点を確定する」で一致率×10が確定
- 「次のお題へ」で次へ
- 最終お題の後は「最終結果を表示」

## チーム運営

- 参加者数に上限はない（チーム数×定員まで）
- チーム数は2以上（目安2〜6、最大10）
- 欠席・遅刻・途中参加はそのまま参加で対応
- 司会者も選手として参加できる
- 途中参加はゲーム終了前なら可能。回答受付中なら現行のお題から回答できる
- チームの追加・定員変更・参加者移動は**ゲーム開始前のみ**（UI）
- チームの削除、参加者の退出・削除、チーム名変更のUIはない
- 回答者4人未満のチームは採点対象外

## 同点順位

1. 総得点
2. 全員一致（10点）の回数
3. 最終お題の得点
4. 抽選

## トラブル対応

| 症状 | 対応 |
|---|---|
| 画面が更新されない | 1〜1.2秒ポーリング。Wi-Fiを確認し、再読み込み |
| 参加できない | ルームコード、URL、Cookieを確認。別ブラウザで試す |
| チームが満員 | 開始前なら定員を増やすかチームを追加。開始後は別チームへ |
| 司会者画面が401 | `HOST_KEY` と `?key=` を確認 |
| スクリーンが401 | `STAGE_REQUIRE_TOKEN=1` の場合は `?token=` が必要 |
| 「画面の状態が古い」 | `PHASE_CONFLICT`。司会者画面を再読み込み |
| Supabaseが停止 | DashboardからRestore。復旧後に再読み込み |
| お題を変更できない | 開始後は凍結。最終結果まで進めて「ゲームをリセット」→お題管理 |
| 参加者が重複 | 同じ端末・同じブラウザで開き直す。解決しなければ司会者がチームを移動 |
| 進行状態が壊れた | バックアップから復元する。`reset-all` は最終結果画面でのみ実行可能 |

## リセット

リセット系のボタンは**最終結果画面にだけ**表示されます。

### ゲームをリセット

- フェーズを `WAITING`
- 参加者・チーム・お題は残す
- 回答・統合・得点・順位を削除
- お題の凍結を解除

同じメンバーでもう一度遊ぶときに使います。

### 参加者も含めて初期化

- 上記に加えて参加者を削除
- チームとお題は残る
- 次のイベントですぐ使える状態になる

> どちらもチーム構成とお題は初期化しません。チーム数を初期値に戻したい場合は、再デプロイ前に状態を初期化してください。

## バックアップと復元

### Supabase

`game_states` テーブルの行をエクスポートします。

```sql
select state from public.game_states where room_code = 'default';
```

復元する場合は、ゲームを止めた状態で同じ行の `state` を保存JSONで更新し、`version` を1つ進めます。

### ファイル保存

`.data/game-state.json` をコピーします。復元時はサーバーを停止してから戻します。

## 障害時のフォールバック

Supabaseが使えない場合、ローカルPCでファイル保存モードに切り替えられます。

1. `.env.local` から `NEXT_PUBLIC_SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` を外す
2. サーバーを再起動
3. `/api/health` が `file` になることを確認
4. 会場の同一Wi-Fiから `http://<PCのIP>:3000` でアクセス

> **既知の制約**: 本番ビルド（`npm start`）はCookieに `Secure` を付けるため、`http://` のLAN接続ではスマホの参加Cookieが保存されない場合があります。その場合は `npm run dev` で起動してください。

ただし、Vercel上の本番ではこの切り替えはできません。会場予備PCにローカル環境を用意しておくと安心です。
