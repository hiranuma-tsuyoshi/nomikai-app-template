## 3. 必須状態

同じ画面でも、状態ごとにフレームを分ける。

### P-04 回答（スマホ）

- `default`：未入力
- `typing`：入力中（文字数カウンター）
- `submitted`：送信済み（送信ボタン無効、「送信済み」表示）
- `closed`：締切後（「受付が終了しました」）
- `error`：通信エラー（「再接続中」）

### P-06 最終確認（スマホ）

- `default`：自分の回答が表示されている
- `editing`：修正中（入力欄が出ている）
- `confirmed`：確定済み（「この内容で確定」を押した後）

### S-04 得点発表（会場）

- `before`：得点表示前（チーム名だけ）
- `after`：得点表示後（+8、83%など）
- `not_scored`：回答者4人未満のチームが「採点対象外」
- `leaderboard`：総合順位（上位3チーム＋4位以下）

### H-05 進行管理（PC）

- `answering`：回答受付中
- `final_check`：最終確認中（残り30秒）
- `revealed`：公開後
- `scored`：得点確定後
- `warning`：回答者4人未満のチームがある

### S-03 回答公開（会場）

- `before_merge`：統合前
- `after_merge`：統合後（「カレー（カレーライス統合）」）

## 4. デザイントークン

`design.md` と `ui-design.md` 9章が正。Figmaでは以下を基準にする。

### 色（参加者スマホ・司会者PC）

| 用途 | 値 |
|---|---|
| 背景 | `#ffffff` |
| 本文 | `#4b4b4b` |
| 補助本文 | `#777777` |
| ボーダー | `#afafaf` |
| 主要（塗り） | `#58cc02` |
| 大見出しの緑 | `#3f8f00` |
| 本文の緑 | `#367a00` |
| ソフト緑 | `#d7ffb8` |
| 青（副次） | `#1cb0f6` |
| 青（リンク） | `#0b78b0` |
| 濃紺 | `#000437` |
| 危険 | `#ff4b4b` |

### 色（会場スクリーン・Kahoot!風ステージ）

| 用途 | 値 |
|---|---|
| 背景 | `#1b0a3d`（深紫） |
| 面 | `#2d1466` |
| 文字 | `#ffffff` |
| 補助文字 | `#c9b8ff` |
| 強調（ピンク） | `#ff3b6b` |
| 強調（イエロー） | `#ffcc00` |
| 強調（シアン） | `#00c4ff` |
| 一致・正解 | `#58cc02` |

チーム色はA〜Fの6色を使う。暗い背景ではチーム色を面で使い、文字は濃紺または白をコントラストで選ぶ。

### 文字

| 用途 | フォント | サイズ |
|---|---|---|
| 表示見出し | M PLUS Rounded 1c 800 | 40–48px（会場96–140px） |
| 見出し | M PLUS Rounded 1c 700 | 24–32px（会場72–120px） |
| 本文 | M PLUS Rounded 1c 500 | 17px（会場48–56px） |
| 補足 | M PLUS Rounded 1c 500 | 13–15px（会場32–36px） |
| 数字・英字 | Nunito 700/800 | 本文に準ずる |

### 形

- 角丸：**12px**
- ボーダー：**2px**
- 影・グラデーション・ガラス表現：**なし**
- 主要ボタン：緑塗り＋濃紺文字
- 副次ボタン：透明＋青文字＋2pxボーダー
- 会場ステージのみ、背景にフラットな円・三角・四角を薄く敷いてよい（影・グラデーションは禁止）

> 緑 `#58cc02` は白背景の本文にはコントラストが足りない。本文は `#367a00`、緑ボタンの文字は `#000437` にする。

## 5. 命名規則

Figmaのフレーム名に**画面ID**を入れる。

```
P-04 回答 / default
P-04 回答 / submitted
S-04 得点発表 / after
H-05 進行管理 / answering
```

画面IDがないと、実装時にどのフレームか分からなくなる。

---

## 6. 共有方法

### Figmaの場合

- 閲覧権限のURLを共有する
- Dev Modeが使えると、余白・文字サイズ・色をそのまま拾える
- コメントは日本語でOK

### Figma以外の場合

- PowerPoint、Excalidraw、手書きスケッチでもOK
- PNG/JPEGのスクショか写真を送る
- 色やサイズが分からなければ、実装側で `design.md` に合わせる

---

## 7. 実装側でやること

- FigmaのレイアウトをTailwindに変換
- スマホは390px幅を基準に、`max-w` と `min-h-dvh` で調整
- 会場スクリーンは16:9を維持し、文字を自動縮小
- ボタン・入力・カードは共通コンポーネント化
- 仮データ（お題・チーム名・回答）を入れて表示
- 実データ接続時に差し替えやすいよう、表示コンポーネントとデータを分離

---

## 8. やらないこと

- Duolingoのロゴ・フクロウ（Duo）・画像素材を使わない
- Kahoot!のロゴ・キャラクター・画像素材を使わない
- Kahoot!の4択クイズUI（色付き4ボタン）をそのまま持ち込まない。うちは自由記述＋チーム一致率
- マーケティングページのレイアウト（800–900pxのセクション、フッター帯）を持ち込まない
- 影・グラデーション・ガラス表現を使わない
- 画面にない要素を実装側で勝手に追加しない（必要なら提案する）

---

**P-04 回答（スマホ・390×844）の `default` と `submitted` の2枚**を作って、FigmaのURLかPNGを送ってください。

それを見て、実装の方向性を合わせます。
